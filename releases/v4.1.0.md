# TradeBlocks 4.1.0

**Bring your own daily data into TradeBlocks, declare when it was known, and use it alongside market fields without looking ahead.**

4.1 adds user daily datasets to the MCP server and causal per-column timing to Static Datasets in the web app. Profile filters, predictive reports, regime analysis and threshold sweeps share that timing contract. It also adds marked-return Monte Carlo, ranked drawdown episodes and offline library calculations for multi-member replay, sizing and walk-forward screening. Existing analysis results can change under the fixes below; read [Behavior changes](#behavior-changes) before comparing a new report with a saved one.

## User daily datasets

Four new MCP tools bring your own numeric or categorical series into analysis:

- `import_daily_dataset`: import an inline CSV (`content`) or a server-readable `csvPath` under the data root, with `name`, optional `ticker`, `columnTiming` and `knownBy`. Supply exactly one of `content` and `csvPath`. Re-importing the same name replaces it atomically.
- `list_daily_datasets`: list datasets, registered fields, timing and coverage.
- `delete_daily_dataset`: remove a dataset and its registered fields.
- `list_analysis_fields`: discover the runtime catalog of built-in market and registered dataset fields, including type, timing and source.

CSV parsing is shared with the web app: the first column is a timestamp, followed by numeric or categorical columns. Fields are named `<dataset>.<column>`. User values live in the `datasets` schema of `analytics.duckdb`; imports never modify market data or require a provider key.

For example, a close-known daily signal:

```json
{
  "name": "signals",
  "content": "Date,score\n2026-10-12,0.004\n2026-10-13,0.009",
  "columnTiming": { "score": "close" }
}
```

Pass those arguments to `import_daily_dataset`, then discover `signals.score` with `list_analysis_fields`. A date-only close observation is available from 00:00 ET on the following calendar day, not during that day's trades. Date-only open columns require a dataset-level `knownBy` time (`HH:mm` ET); timestamped rows are as-of. Each column carries its latest available nonblank observation forward across missing days and non-trading days, with no freshness cutoff.

Profile filters resolve dataset fields independently of built-in market coverage, so dataset-only filters work without market rows. `enrich_trades` preserves custom fields and exposes dataset values with source and availability timestamps. Aggregate dataset analyses report per-field attachment counts, median/max Eastern calendar-day age and counts older than three days. Age is visibility, not an expiry policy.

See the [MCP tools reference](../docs/mcp-tools.md#market-analysis) for inputs and field usage.

## Behavior changes

### Profile-filter close-field lookahead fix

**Bare close-derived comparison operands now always use prior-day values.** Before, a cross-field filter such as an open-known field compared with a bare close-derived field preferred the raw same-day close when present in the joined record. It now resolves that operand through its `prev_` value even when the raw same-day field exists. A missing prior observation stays unavailable; it never falls back to today's close. `validate_entry_filters` and other consumers of these cross-field predicates can therefore select different trades and report different results.

### `validate_entry_filters` covered-pool baselines

Every comparison and ablation now uses the same pool of trades covered by **all resolvable requested filters**, including any cross-field comparison operands. `no_filters`, per-filter passing/failing slices, the all-filters baseline, and single/pair ablations stay on that pool. Removing a filter no longer admits rows merely because its observation was missing. Coverage remains per field: unrelated dataset values cannot inflate built-in baselines or hide missing-market warnings.

### Unknown profile filter fields are reported

`validate_entry_filters` names unknown fields and reasons in `unresolvable_filters`, warnings and the summary, excluding them from per-filter results and ablation rather than letting them empty known-filter baselines. If none are resolvable, it returns `error: "no_resolvable_filters"` naming the fields. `analyze_structure_fit` likewise reports unknown profile dimensions while retaining its fixed and known-field dimensions. Unknown fields are distinct from known fields with missing observations; execution-only filters remain excluded from market-filter validation.

### `filter_curve` threshold precision

Auto-generated percentile thresholds are no longer rounded to two decimal places. `filter_curve` and generic `suggest_filters` sweeps share scale-preserving interpolated thresholds, so small-valued series no longer collapse into rounded duplicates. Thresholds, selected cohorts and their metrics can change even for existing trade fields. Unknown or entirely uncovered registered dataset fields are refused by name rather than yielding a misleading empty result.

### `analyze_structure_fit` coverage and hint baselines

The `time_of_day` dimension now includes every trade with a valid entry time, including trades without a built-in market row; it does not need market data. Other dimensions use their own observed field values. The additive `dimension_baselines` reports each dimension's covered baseline, and update hints compare buckets against that dimension's baseline rather than the overall pool. Results and hints can change for partial-coverage books.

### `find_predictive_fields` ranks built-in market fields too

Predictive ranking now includes the runtime catalog's **built-in market fields as well as registered dataset fields**, in addition to existing trade/custom fields. Numeric fields with enough observations participate in ranking; insufficient fields are reported as skipped. `find_predictive_fields`, `filter_curve` and `get_field_statistics` resolve market and dataset observations causally at trade entry, populating the Static Dataset field slot and per-field age summaries. Ranked order, analyzed-field counts and top results can change; this is not only an additive dataset result. Existing trade-field statistics keep their output shape.

### Static Dataset declared timing and `legacy-same-day`

New web imports declare open/close timing for every column, defaulting to close, under the same date-only/as-of rules as MCP imports. Declared datasets always use the latest value available at entry, regardless of stored match strategy; the web app disables strategy selection and explains why. Blank cells are not observations.

Existing IndexedDB datasets retain their stored numbers and load as `legacy-same-day`, with a visible lookahead warning and a **Set column timing** action. Older imports did not preserve source precision, so setting timing requires choosing dates-only or timestamped rows; mixed-precision legacy files must be re-imported. Same-day, nearest-after and nearest modes remain available only for legacy datasets, labelled non-causal. Declaring timing can change attachments and downstream analysis, but does not rewrite user values.

Library exports add `validateDatasetTiming`, `getDatasetValueAvailableAt`, `resolveDatasetColumnAtTime` and `updateStaticDatasetTiming`. Resolver inputs are immutable snapshots. The explicit column resolver refuses unknown columns; `getMatchedFieldValue` still returns null for unknown fields or unavailable observations. Daily-log custom fields remain same-day joins without timing metadata and can leak close-derived values: use timed Static Datasets for causal analysis.

### Drawdown attribution reports the selected episode's equity

`drawdown_attribution.drawdownPeriod.peakEquity` and `troughEquity` now belong to the selected episode, not the highest equity reached anywhere later in the log. Selection, dates, drawdown amount/percentage and legacy strategy attribution are unchanged. The selection rule is the largest **dollar** drawdown on closed-trade reported-P/L equity in close-date/time order, not percentage-ranked or taken from daily NLV. The public `buildRealizedDrawdownAttributionByCloseDate` calculation receives the same correction.

### Massive quote-fetch failures are not empty successes

Massive per-ticker `fetch_quotes` output adds `requests[]` receipts with ticker/date, `outcome` (`ok`, `empty`, `error`), minute `rows`, decoded `pagesFetched` and optional `httpStatus`/`errorClass`. HTTP, payload, network, timeout and pagination-limit failures now report errors. Failed requests discard their fetched pages before enrichment and quote-cache writes; successful other dates remain available. Mixed results return `partial`; all-failed requests return `error`; genuine empty successes remain `ok` with zero rows.

Both NBBO and `synth_close` report outcomes. NBBO date iteration preserves requested calendar days in every host timezone; skipped weekends emit no receipt and cannot count as a success. `synth_close` retains its single paginated range fetch: each date receipt carries the range page count, and any page failure discards all range rows and marks every date as error. Successful quote values, ThetaData, retry/tier policy and the provider Map return remain unchanged. An optional `fetchQuotes` observer carries receipts without discarding good dates. Integrations remain opt-in; CSV import still needs no provider key.

## More analysis with your fields

- `analyze_regime_performance` accepts registered fields alongside existing presets. Numeric fields use declared cut points or quantile bins; categorical fields group by value. Causal entry-time values, partial coverage and named unknown/uncovered errors are shared with other field analyses. Existing preset calls remain unchanged.
- `suggest_filters` takes optional `fields` to sweep registered numeric or categorical fields, reporting coverage and refusing unknown or wholly uncovered fields. Omit `fields` to retain existing defaults.
- `get_field_statistics` reports dataset distributions and per-field age using the same resolved observations as predictive and sweep tools.

## Portfolio risk tools

### Marked-return Monte Carlo

`run_monte_carlo` adds opt-in `resampleMethod: "marked-daily"` for stationary-block bootstrapping of an imported whole-portfolio daily log. Returns use the `get_statistics` formula, `dailyPl / (netLiquidity - dailyPl)`, with zero for a nonpositive denominator. Deposits/withdrawals are not independently adjusted; their effect remains in reported NLV.

Missing/short logs, rows lacking reported daily P/L, strategy filters, iid resampling, one-lot normalization and explicit trade-derived worst-case injection are refused, never replaced by trade P/L. Output declares a replayable seed, effective mean block length, observation horizon and decimal units, with per-path maximum-drawdown p50/p95/p99 and horizon-return p5/p50/p95/p99. Existing methods, defaults and seeded responses are unchanged.

The library exports `dailyLogReturns`, shared by portfolio statistics and the tool. `runMonteCarloSimulation` accepts fewer than ten trades when a **nonempty** `precomputedReturns` series is supplied with `resampleMethod: "percentage"`; the return pool must still contain at least five observations. An empty supplied series retains the legacy trade-derived fallback and ten-trade guard. Existing valid precomputed-series consumers keep their sampler and seeded results.

### Ranked drawdown episodes

`drawdown_attribution` accepts optional `episodeCount` (integer 1–20), adding a dollar-depth-ranked `episodes` list. `topN` limits contributors per episode; omission preserves the legacy shape, with the equity correction described above. The library's `buildRealizedDrawdownAttributionByCloseDate(trades, topN, episodeCount?)` exposes the same capability.

Recovery to or above a previous peak ends an episode; an unrecovered final episode has null recovery date. Dollar-depth ties prefer the earlier peak trade; equal peaks use the latest trade, equal troughs the earliest. Exact close timestamp ties retain input order. Each list item carries its own peak/trough equity and dates, depth, percentage, recovery and strategy attribution. List attribution uses only trades after the peak through the trough, so full-period P/L reconciles to negative depth; contributor truncation does not change period totals. Legacy single-episode attribution retains its inclusive-date window, whose P/L can differ from negative depth. These are realized-trade episodes, not marked-account episodes.

### Marginal expected shortfall

`marginal_contribution` accepts opt-in `includeTailRisk: true` and `tailConfidence` (default 0.95). The added `tailRisk` reports baseline and removed-strategy CVaR/expected shortfall on the same realized, net-after-fee return series used for each arm's Sharpe/Sortino, with original initial capital and each arm's own close-date extent. Invalid confidence errors; empty arms report null with a reason.

This is **incremental, leave-one-out, non-additive** analysis, not Euler or marked-account attribution. Signed decimal `changeVsBaseline` is removed-arm ES minus baseline ES: a positive change means removal reduces tail loss. Changes do not sum to book ES. Without the opt-in, responses and ratio calculations are unchanged.

`PortfolioStatsCalculator.calculateDailyReturnsWithDates(trades, dailyLogEntries?)` becomes public, retaining close-date grouping, prior-equity denominators, business-day filling and weekend handling. Its basis-aware net mapping deducts gross-before-fees commissions once and does not charge already-net trades again, without mutating caller trades.

## Offline multi-member library calculations

4.1 exports `replayBook`, `searchBookAtDrawdown`, replay calibration, risk-budget sizing and book walk-forward calculations through `@tradeblocks/lib` and its calculations entrypoint. These are offline calculations, not new MCP tools or provider integrations. Results screen and order candidates; they are not broker or backtester evidence. The [Developer Guide](../docs/development.md#offline-book-replay-and-drawdown-budget-search) documents their interfaces and units.

### Replay, marks and effective-dated sizing

`replayBook` replays whole-contract member entries against one shared funds/buying-power ledger. Optional controls include:

- `includeFundsAtEntry: true`: adds the closed funds used at each `contractsPerEntry` attempt, including zero and disabled attempts, after same-timestamp closes settle and before minimum-one, caps and admission. This is neither marked equity nor buying power remaining after reservations. Opens reserve buying power without spending closed funds.
- `memberMarkedPl: true` alongside `marks`: adds per-member daily net-dollar P/L aligned with replay dates and actual executed quantities, reconciling to aggregate marked-equity change including day one from starting funds. It includes partial closes and ignored mark-only drop-off; removed/zero-quantity members receive zero series. Without marks it explicitly errors. Missing marks remain errors, not fills or invented closes.
- `sizingSchedule`: selects the latest effective-date sizing/caps per real member, with the base rule before the first date. Admitted positions keep quantities, reservations and normal closes across rule changes; funds, marks and concurrency stay continuous. Flags such as `removed`, `ignoreMarginRequirements` and `minimumOne` cannot vary by schedule.
- `{ effectiveDate, disabled: true }` in a schedule: admits no new groups, without forced exits or concurrency resets. Sizing/caps are optional and ignored while disabled; reinstatement supplies complete active sizing/caps. `disabledGroups` appears only when disabled entries are supplied, separate from active `zeroGroups`. Search and equal-standalone-risk sizing refuse schedules.

Invalid, duplicate or unsorted schedule dates, unknown members and invalid declarations are refused. Optional reporting leaves execution unchanged; omitting the controls retains their default output shape.

Corporate-action rows require caller normalization, not an automatic adjustment field: normalize net P/L and open marks to the entry-contract basis while retaining entry-basis sizing/buying power. A public-entrypoint regression pins TSLA's 3-for-1 case: two entry contracts reproduce six adjusted contracts' $120 settlement and $140 open mark. Replay reports entry quantities; callers keep adjusted quantities for settlement displays.

### Drawdown-budget search and resumable progress

`searchBookAtDrawdown` is a bounded best-observed search, not a certified global optimum. Its required `objective` selects `returnPct` or `returnOverDrawdown`. The latter ranks realized return against marked drawdown when marks are supplied, otherwise closed-equity drawdown, under the declared feasibility and drawdown ceiling. Positive-return/nonpositive-drawdown candidates rank first by return, positive-drawdown candidates next by signed ratio, and nonpositive-return/nonpositive-drawdown candidates last by return. Exact ties keep the first observed candidate; non-finite ratios throw. Ratio results add `objectiveTier`, `objectiveValue` and the declared drawdown basis. Generic input/result types default to the `returnPct` literal.

`memberCapPolicies` can hold selected `maxContractsPerTrade` caps `fixed` while sizing follows search weights, including coordinate, robust, drop-one and stability/sensitivity searches. Omitted policies retain scaled caps; zero weight removes a member, null stays uncapped and dollar allocation caps still scale. Unknown members/policies are refused.

Optional `onProgress`, `checkpoint`, `resumeFrom` and `feasibleId` controls expose committed evaluations and detached version-2 JSON checkpoints. Lazy `event.checkpoint()` copies only when requested; journals retain compact metrics/verdicts rather than full replays. Resume validates the complete economic request and constraint identity, reconstructs deterministic control flow and reuses saved evaluations. Changed requests, trade order, objective or feasibility presence refuse resume with `search_checkpoint_identity_mismatch`. A feasibility policy requires `feasibleId` for checkpoint-capable calls before any evaluation. Throwing progress callbacks abort with `search_progress_callback` and the original cause; save the committed event's checkpoint first. Journals grow linearly; saving a full snapshot every evaluation still entails quadratic total copying.

### Reusable prepared tapes

Search prepares invariant replay data lazily at its first uncached evaluation; robust and drop-one evaluations reuse it, while bootstrap replicates prepare their own resampled tapes. `prepareReplayTape(input)` returns an opaque frozen runtime handle for `replayBook(input, { preparedTape })` or search options. It is detached from caller input and held privately, not a serialized checkpoint or input-identity cache.

Each call checks the full canonical invariant declaration and fingerprint, including dates, economics, identity, marks, ordering, starting funds and tape policies; mismatches throw `prepared_replay_tape_mismatch`. Member sizing, caps, flags, schedules and reporting controls can vary and are validated per call. Use separate handles for different ignored-buying-power hypotheses. Mutable replay state stays fresh for every candidate; reuse does not add parallel search execution.

### Risk-budget sizing

`sizeBookAtEqualStandaloneRisk` fits a common standalone marked-drawdown or loss-positive decimal ES target over explicit finite member-weight domains, then selects a common book factor over a declared finite domain. It is CPC-only for all-CPC books, keeps fixed contract caps and whole quantities, and reports reference/final standalone risks, residuals, budget attainment, cap counterfactuals and zero groups. A common factor does not promise exact final equality; failure is **not attained within domain**, not global infeasibility.

An optional deterministic, non-mutating `feasible` policy accepts `true`, `false` or `{ ok: false, reason }`, applying to both standalone references and book candidates. Invalid verdicts throw; supplied policies add stage-specific rejection counts/reasons. Standalone policies must exempt removed members. No checkpoint or `feasibleId` is added to this helper.

Optional `bookBudgetRisk` independently selects stage-two marked maximum drawdown (percentage points) or book ES (loss-positive decimals at a declared confidence), while standalone fitting retains `risk`/`standaloneTarget`. Explicit declarations report both units and the book risk-minus-budget residual. Omitting the option retains the same metric for both stages.

`bookExpectedShortfallContributions` decomposes fixed-position book ES on the book's own discrete tail days and prior book equity, including starting funds on day one. It includes all cutoff ties, no fractional weighting, preserves negative offsets and reports reconciliation residuals. This is not sensitivity to replay CPC/weights or contribution-based retuning.

`nominalCapitalPerContractFromPercentagePoints` uses percentage points (2 means 2%) and the median of caller-selected per-contract buying-power rows. It is descriptive, not allocation-admission or actual-exposure equivalence.

### Causal book walk-forward and optional audit

`walkForwardBook({ input, folds, fit, policies, initialRules? })` calls a caller-owned fit using only training sessions strictly before each fold origin. Future closes are redacted to an out-of-axis close with zero P/L; future marks are removed, while already-known marks on still-open positions remain. Unavailable fits carry previous or initial rules with reasons and affected members.

Frozen fold rules become one `sizingSchedule`, replayed once per ignored-buying-power policy through a continuous real-member ledger. Funds, held positions and concurrency persist across folds. Results report fold attainment, active zero-quantity versus disabled participation, and a logical computation ledger.

`fitBookAtEqualRisk(training, recipe, previous?)` supplies an equal marked-drawdown recipe with declared factor search, rounding and repair. Required `noTrainingEntries` selects `unavailable` (name empty members and refuse the fold) or `carry-member` (fit others and retain empty members' prior rules). The fit budget excludes carried members; replayed drawdown measures the combined schedule.

`replayBook(input, { audit })` accepts `BookReplayAudit` for detached, deeply frozen entry-sizing and session-opening held-position facts. `ReadonlyFact<T>` distinguishes unknown from measured zero and absent caps. Invalid/duplicate origins are refused; callback failures abort. Omission allocates no audit facts and does not change execution or fees. `walkForwardBook(request, { audit })` forwards policy-labelled audit only to final continuous replays, not fitting/search. The audit types and `WalkForwardBookOptions` are exported; callbacks do not enter declarations, tape identity or checkpoints.

### Replay calibration

`compareReplayToNative(expected, observed, tolerances?)` compares provider-neutral normalized ledgers. It names missing/extra entries, member/whole-contract quantity differences, cent-precision per-unit net P/L differences, ending cash, terminal positions and curve-date mismatches. Both marked drawdowns use the same running-peak calculation with a default inclusive 0.01-percentage-point tolerance; every dated equity residual and maximum-episode peak/trough residual is reported. Invalid ledgers/tolerances throw; missing dates fail explicitly, not by silent intersection. Normalization, evidence retention and tolerance policy stay with the caller.

## Additional public calculations

- `cvarFromReturnsAtConfidence(returns, confidence)` returns signed-decimal CVaR at any finite confidence strictly between 0 and 1. It linearly interpolates the lower-tail cutoff and averages all observations at/below it, including ties, without fractional weighting. Invalid confidence throws `RangeError` even on an empty series; valid empty input returns undefined, a single observation itself. The one-argument `cvarFromReturns` retains its exact 95% arithmetic and point-free callback use.
- `holmAdjust(pValues)` performs stable Holm step-down family-wise adjustment in input order, with a running maximum and cap at one, without mutating input. Empty input returns an empty array; non-finite/out-of-range p-values throw `RangeError` naming the index. Callers define the family and handle unavailable p-values; bootstrap outputs/options are unchanged.
- `runMonteCarloSimulation` accepts opt-in `includeMaxDrawdownQuantiles: true`, adding top-level p50/p95/p99 nonnegative decimal drawdown depths without changing `statistics`. `pathQuantiles` exports the shared p5/p50/p95/p99 interpolation at rank `(N - 1) * p`, sorting a copy and refusing empty input. Marked-daily MCP summaries use the same implementation. Sampling and other seeded outputs remain unchanged.
