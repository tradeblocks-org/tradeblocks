# Tradeblocks 3.10.2

## An idle copy of the server no longer blocks writes in the others

3.10.1 stopped two copies of the MCP server from shutting each other down. This is
the other half: making writes work while more than one copy is running.

The analytics database allows any number of readers at the same time, but a write
needs the file to itself — and a copy that is only _reading_ is still in the way.
Until now, each copy opened the database when it started and held it open for as long
as the process lived. So a copy you were not using at all — a Claude Desktop window
sitting in the background — blocked every data import, market refresh, and sync in
every other copy. The failure looked like this, and no amount of waiting cleared it:

```
Cannot acquire DuckDB write lock. Another tradeblocks-mcp server holds the database
```

A copy now lets go of the database a few seconds after it stops being used, and
picks it up again the moment it has something to do. Reopening takes about ten
milliseconds, which is far less than any tool call, so nothing feels slower. The
practical effect: an idle copy is no longer in anybody's way, and a write in one copy
waits its turn rather than failing.

Two consequences worth knowing:

- **A write can still be refused if another copy is genuinely busy.** Two copies both
  doing real work still contend, because that is what exclusive access means. The
  write now waits about ten seconds before giving up rather than four. Run the tool
  again once the other copy has finished.

- **You no longer have to quit anything.** The previous release's advice — that the
  other server had to exit before a write could go through — no longer applies.
  Leaving it open and unused is enough.

Two new settings, for a data directory shared by unusually busy servers:

| Variable                    | Default | What it does                                                      |
| --------------------------- | ------- | ----------------------------------------------------------------- |
| `DUCKDB_IDLE_RELEASE_MS`    | `3000`  | How long a copy keeps the database open after it stops being used |
| `DUCKDB_WRITE_LOCK_RETRIES` | `10`    | One-second attempts a write makes before giving up                |

Raising the first makes writes in other copies wait longer, which is the trade-off
this release exists to remove — leave it alone unless you have a reason. If you do
raise it, raise the second to match.
