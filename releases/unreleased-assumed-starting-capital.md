# Unreleased — evidenced MCP starting capital

**Behaviour change to existing `get_statistics.stats.initialCapital`.** For a trade CSV without `Funds at Close`, it is now a positive starting balance rather than a negative or zero inference from the loader's placeholder. On an unfiltered block with a usable daily log, the start remains first-day `netLiquidity - dailyPl`; otherwise the two MCP tools use an explicitly assumed $100,000. A real numeric zero after a first-trade loss is still an observed balance, not a missing field. A nonpositive or non-finite inference is assumed, never labelled observed. Existing funded blocks retain their previous capital and trade-realized chart behavior. Fee-aware net P/L still deducts fees once according to the declared P/L basis.

`get_statistics.calculationMethodology.initialCapital.source` and `get_performance_charts.equityCurveCapitalSource` are additive fields with values `observed_trade_funds`, `daily_log`, or `assumed_default`. The equity curve remains trade-realized, not the daily log's marked account equity. The MCP subset-equity rebuild now also starts missing-funds subsets at the assumed amount; independent Monte Carlo, health, period segmentation, browser snapshots and the public calculator's other readers retain their existing capital inference. The library's exported realized curve accepts an optional explicit starting amount for the MCP chart; callers omitting it retain their previous calculation.

No version or publication is made by this note.
