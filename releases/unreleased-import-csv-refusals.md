# Unreleased — `import_csv` refuses unloadable CSV rows

**Behaviour change to existing `import_csv` input acceptance.** Trade logs and reporting logs now refuse an impossible opened/closed calendar date or missing/unparseable P/L; gross-before-fees trade rows also require parseable opening and closing commissions. A daily log with a missing or unparseable value refuses the whole import. Errors identify the CSV file line (including the header), and no block is created, even for a paired import. Previously an impossible date could create a block that failed to sync, while invalid P/L or daily-log values could silently become zero.

`Portfolio Value`, `Value` and `Equity` daily-log columns now load as net liquidity in imported and folder-discovered blocks. Folder loading skips daily-log rows without a parseable value rather than fabricating zero; folder-discovered trade acceptance and DuckDB sync row counts are unchanged. Successful receipts count actually loaded trades and use the block ID, rather than the display name, when a trade has no Strategy. Valid Option Omega exports continue to import without a provider key. This note does not bump a version or publish a release.
