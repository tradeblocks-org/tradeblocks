# TradeBlocks 4.6.2

Fixes shifted weekday labels and weekday filter suggestions in the MCP server. Thanks to steffdax for the report.

## What was wrong

`analyze_regime_performance` with `segmentBy: "dayOfWeek"` interpreted stored weekdays one day too early: Tuesday appeared as Monday, Wednesday as Tuesday, Thursday as Wednesday, and Friday as Thursday. Monday appeared as `Day 1`.

In `suggest_filters`, **Skip Mondays** actually removed Tuesdays. **Skip Fridays** targeted value 6 (Saturday), so it did not remove Friday trades.

## Corrected behavior

- Weekday segment labels now match the trade's market date.
- **Skip Mondays** targets value 1; **Skip Fridays** targets value 5.
- Tool and schema descriptions document the existing JavaScript convention: 0=Sunday, 1=Monday through 5=Friday, 6=Saturday.

Stored `Day_of_Week` values are unchanged. No migration or re-enrichment is needed. Update the MCP server, restart it, and rerun affected analyses; earlier returned labels and weekday-filter results remain incorrect. Review any user-authored numeric weekday filters based on the old documentation rather than shifting stored data.

No tool inputs, provider requirements, market-data joins, lookahead rules, trade P&L or commissions change. Existing named profile filters and profile weekday analysis already used Monday=1 through Friday=5 and remain unchanged.
