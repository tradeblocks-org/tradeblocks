# TradeBlocks 4.5.1

**Option fetches and imports work without `TRADEBLOCKS_PARQUET`; SPX-root replay resolves the appropriate SPXW contract or refuses explicitly, and explicit-leg replay works after an idle connection release.**

4.5.1 fixes option storage on default installations and replay failures that could look like zero-valued results. Option data remains local to your data directory, and replay remains cache-only: backfill missing quotes with `fetch_quotes` or compatible local imports before replaying.

## Behavior changes

### Option storage needs no environment setting

Option-chain and minute-quote fetches (including bulk quotes) and option flat-file imports always write Parquet partitions. Previously, leaving `TRADEBLOCKS_PARQUET` unset could download data and then fail with a missing `option_chain` or `option_quote_minutes` table. No setting or setup change is required.

`TRADEBLOCKS_PARQUET=true` remains optional and defaults off. It switches spot/enriched writes to Parquet and metadata/profile storage to JSON; it does not control option storage. CSV-only imports still require no provider credentials.

Fresh archives return an empty chain through the store reader before the first chain publication. The canonical option publisher registers a missing SQL view after the first write; existing views are reused without rescanning partitions on every write. Quote merge/replacement, atomic publication, sorting, provenance and caller-serialization contracts are unchanged.

### SPX-root replay resolves SPXW without interchanging monthly contracts

Option Omega tradelogs record the underlying as `SPX`, while weekly and daily PM-settled contracts are listed as `SPXW`. When an `SPX`-root leg on one of those expirations has no usable `SPX` quotes, replay uses usable quotes for the corresponding `SPXW` contract. The output leg's `occTicker` identifies the contract replayed. This applies to tradelog mode and explicit legs.

The `SPX` root lists the AM-settled monthly contract: the third Friday, or the Thursday before it when that Friday is an exchange holiday. It is not interchangeable with the PM-settled `SPXW` contract expiring that day. On a possible monthly expiration, replay never substitutes `SPXW` for missing `SPX` quotes; the error names the `SPXW` contract so callers can specify `ticker: "SPXW"` explicitly when that is the intended contract. Outside the bundled calendar, the Thursday before the third Friday is conservatively treated as a possible monthly expiration. `NDX` and `RUT` legs still match only their exact roots.

### Missing quotes are errors, not zero-valued results

Previously, a replay with an unavailable leg could return an empty path with MFE, MAE and P&L all zero and no warning. Failed quote reads could produce the same misleading result. Replay now reports an error identifying unavailable legs and why: no cached rows, no usable rows with positive bid and ask from 09:32 ET, or no replay path at or after entry. Failed quote reads report the underlying database error.

- `analyze_exit_triggers` and `decompose_greeks` propagate the replay error instead of reporting no P&L data or a zero decomposition.
- `batch_exit_analysis` lists affected trades under `skippedTrades` with the error message and excludes them from its aggregate.
- `get_greeks_attribution` counts affected trades in `trades_skipped`. Its `total_pnl`, `mark_total_pnl` and `execution_edge` exclude them instead of treating missing marks as zero factors and attributing their actual P&L to execution edge.

### Explicit-leg replay reopens idle connections

Replays with `legs` previously failed with "No active DuckDB connection" after the server released its database handle while idle (about three seconds). They now reopen the handle as tradelog replay does. Idle handle release remains enabled.

## Existing option data on upgrade

On read-write startup in either storage mode, physical option-chain tables from older releases are migrated through the canonical publisher before any view can replace them. The source is dropped only after every row has been published.

Existing Parquet partitions are never merged or overwritten by this migration. Nonoverlapping partitions are published, and the original table is retained under `option_chain_legacy_retained_<id>` if any partition overlaps, fails publication or publishes an unexpected row count. Its exact name is reported on stderr for inspection and reconciliation. A retry after an interrupted copy conservatively retains the source when an already-copied partition exists. Archives with date-only `option_chain/date=…` partitions retain the source without publishing because the two partition layouts cannot be read together.

No released public version created a physical option-minute-quote table. A populated table from a nonstandard installation is retained under `option_quote_minutes_legacy_retained_<id>` and named on stderr rather than guessing its schema or deleting its data. Direct view registration refuses to replace populated option tables that have not been migrated or retained.

## Compatibility

- Callers that used an empty `pnlPath` as a no-data signal must handle replay errors instead. Successful replays retain their output fields and formats; SPX-root legs resolved to SPXW report that resolved ticker.
- The `tradeblocks-mcp/test-exports` entrypoint no longer exports `DuckdbChainStore` or `DuckdbQuoteStore`. Use `createMarketStores`, or `ParquetChainStore` / `ParquetQuoteStore`, and do not manufacture physical option tables in fixtures.

See [storage, configuration and replay guidance](../docs/market-data.md) and the [MCP server setup guide](../packages/mcp-server/README.md).

## Bundled rates

Bundled Treasury bill (DTB3) rates are refreshed through October 26, 2026, and SOFR through October 27, 2026. The release freshness check requires bundled rates to be within ten calendar days of published data.
