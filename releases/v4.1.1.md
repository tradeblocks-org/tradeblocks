# TradeBlocks 4.1.1

**A single-ticker quote fetch no longer deletes every other contract's quotes for that date.**

This patch fixes a data-loss bug in the Parquet option-quote store. Upgrade if you use `fetch_quotes` against a store that already holds full-day option quotes.

## Single-ticker quote writes keep the rest of the partition

Option minute quotes are stored as one Parquet file per underlying and date, at `market/option_quote_minutes/underlying=X/date=YYYY-MM-DD/data.parquet`. Up to 4.1.0, writing quotes for one contract (for example `fetch_quotes` with a single OCC ticker) replaced that whole file with the new contract's rows. Every other contract stored for that underlying and date was lost: a full SPX day of several million rows could shrink to a few hundred.

From 4.1.1:

- A quote write replaces all minutes of exactly the tickers it carries and keeps every other ticker's rows unchanged, including their stored Greeks and source and rate provenance. Retained rows keep their stored precision. When retained rows carry legacy DOUBLE Greeks, the incoming Greeks in that file are stored as DOUBLE too.
- A multi-ticker `fetch_quotes` collects accepted rows and publishes each partition once. If pending rows reach 32,768 after a complete ticker, it flushes early, so memory stays bounded by that threshold plus one ticker's batch. Rows from tickers that already succeeded are still published when a later provider request fails.
- Quote-partition writes are read, merge, then replace, and there is no per-partition lock. Callers must serialize concurrent writers to the same underlying and date.

## Destructive shrinks are refused

Both quote-store writes and whole-partition flat-file quote imports now refuse to publish a partition with fewer than half the existing rows. The refusal is `QuotePartitionShrinkError`, and its message names the partition, the existing and candidate row counts, and the 0.5 threshold. The existing file is left untouched.

- Exactly half is accepted.
- Fresh or empty partitions are accepted, and so is growth from any size, including full-day imports that restore previously truncated data.
- There is no override.
- If the existing partition file is unreadable, both write entrances refuse with the underlying DuckDB error and leave the file in place. Move the corrupt file aside before re-importing that date.

## Behavior changes

- A quote write that would leave a partition with fewer than half its rows now throws `QuotePartitionShrinkError` instead of truncating it.
- Tool inputs and outputs are unchanged. No provider becomes mandatory, and CSV import still works without a market-data key.

This release does not recover quotes already lost to the bug. To restore an affected date, re-import the full day from your provider. See the [Market Data Guide](../docs/market-data.md#quote-partition-writes-and-shrink-protection).
