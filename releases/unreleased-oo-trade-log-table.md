# Unreleased — OO capture reads Option Omega's 2026-09-29 trade-log table

- The optional `tradeblocks-skills` `oo-capture` plugin works again on Option Omega's 2026-09-29 MCP schema, verified against OO staging (a saved backtest of 191 trades, a saved portfolio of 237 trades with three members, and a scratch run of 24 trades reconcile to OO's headline count and net profit to the cent). OO's `get_trade_log` now returns a `tradeColumns` header plus `trades` rows instead of `items` objects. Before the plugin change, capture saved the pages but verification refused `INVALID_PAGE` on every OO source, so `bring-in-oo-backtest`, `is-this-optimum-real`, `stress-oo-portfolio`, `live-vs-oo` and `allocate-oo-portfolio` could not bring in a fresh OO capture. The capture reads each row by its column name, refuses a column it does not recognise (`UNKNOWN_COLUMN`) or a missing required column (`MISSING_COLUMN`) by name, and its page-by-page hook message now reports source, sort, offset, row count, total and `nextOffset`.
- The `Legs` cell of a captured trade log changes format. It used to be `<side> <contracts> <expiry> <strike> <type> @ <price>` joined by `; `, built from per-contract leg prices that OO no longer sends. It is now OO's own leg text, for example `1 Feb 6 5850 P STO 2.45 | 1 Feb 6 5840 P BTO 1.20`: the text OO's CSV export writes and the form the `replay_trade` leg-string parser reads, so a captured log now replays like an OO CSV import. Leg prices in that text are OO's per-share quotes, not per-contract dollars; leg deltas are no longer provided by OO and are not reconstructed.
- Capture verification is otherwise unchanged: complete paging in one fixed ascending sort, count and net profit to the cent (book and every portfolio member), `isIgnored` trades excluded, `profit` net of fees with no second deduction, OO's `profitPercentage` as `P/L %` (blank when OO's cell is null).

No tool, prompt or argument in the TradeBlocks MCP server changes. This note does not bump a version or publish a release.
