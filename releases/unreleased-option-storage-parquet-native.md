# Option storage works without an environment setting

- Option-chain and minute-quote fetches (including bulk quotes) and option flat-file imports always write Parquet partitions under the data directory. Previously, leaving `TRADEBLOCKS_PARQUET` unset could download data and then fail with a missing `option_chain` or `option_quote_minutes` table. No setting or setup change is required.
- `TRADEBLOCKS_PARQUET=true` remains an optional switch for spot/enriched Parquet writes and metadata/profile JSON storage, default off. CSV-only imports still need no provider credentials.
- Fresh archives in either mode expose an empty chain through the store reader before the first chain publication. The canonical option publisher registers a missing SQL view after the first write; existing views are reused without rescanning partitions on every write. Quote merge/replacement, atomic publication, sorting, provenance and caller-serialization contracts are unchanged.
- On read-write startup in either mode, physical option-chain tables left by older releases are migrated through the canonical publisher before any view can replace them. The source is dropped only after every row has been published. When a partition already exists, it is not merged or overwritten: the original table is retained under `option_chain_legacy_retained_<id>` and its exact name is reported on stderr. Nonoverlapping partitions are still published. A retry after an interrupted copy conservatively retains the original table if a previously copied partition now exists. The table is also retained, without publishing, when the archive has date-only `option_chain/date=…` partitions (the two layouts cannot be read together), and when a partition fails to publish, so startup still completes.
- No released public version created a physical option-minute-quote table. If a nonstandard installation has one, startup retains it under `option_quote_minutes_legacy_retained_<id>` and reports its exact name on stderr rather than guessing its schema or deleting its data. Direct view registration refuses to replace populated option tables that have not been migrated or retained.
- For consumers of `tradeblocks-mcp/test-exports`, `DuckdbChainStore` and `DuckdbQuoteStore` have been removed. Use `createMarketStores` (or `ParquetChainStore` / `ParquetQuoteStore`); do not manufacture physical option tables in fixtures.
