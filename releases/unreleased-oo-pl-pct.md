# Unreleased — trade P/L % uses Option Omega's own value

**Behaviour change to trade `plPct` for CSVs carrying a `P/L %` column.** When a trade log has Option Omega's `P/L %` column and a trade's cell is numeric (`97.905…` means 97.9%), that value is now the trade's `plPct` in the Report Builder, What-If explorers, threshold analysis and the MCP report tools (`get_field_statistics`, `find_predictive_fields` and `filter_curve`). Before, the web importer ignored the column and the MCP server stored it as the custom field `P/L %`; both recomputed `plPct` as P/L ÷ |Premium × No. of Contracts| × 100. The column stays optional: without it, or for a blank or unparseable cell, `plPct` is that same computed value, and `import_csv` never refuses a row because of it. The `premiumEfficiency` alias follows `plPct`; `netPlPct` is still computed from net P/L. MCP trade logs no longer expose `P/L %` as the custom field `custom.P/L %`. Existing browser blocks keep their computed values until the source CSV is re-imported; MCP folder blocks read the column on their next load. Web backups from `exportTradesToCSV` now include the `P/L %` column. This note does not bump a version or publish a release.
