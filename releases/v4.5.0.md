# TradeBlocks 4.5.0

**Large multi-entry blocks can finish filter analysis instead of spending their time resolving unrelated fields: score entry days, compare daily risk, and inspect the chosen filter by regime.**

4.5 addresses large-block latency with field-scoped resolution, reusable Eastern-time formatters and work admission before enrichment. `filter_curve` adds `unit: "day"`, the daily risk objectives `sharpe`, `mar` and `maxDrawdown`, and `groupBy` / `perGroup` breakdowns. These remain screens on a supplied trade tape, not new backtest results. Confirm a surviving filter in a native Option Omega backtest; the local tools do not require an OO connection.

## Behavior changes

### Explicit-field tools resolve only the fields they use

`filter_curve` now resolves its requested filter/group fields rather than all registered dataset columns for every trade. The same field-scoped resolution applies to `get_field_statistics`, explicit-field `suggest_filters`, `analyze_regime_performance`, and profile fields plus cross-field comparison operands used by `validate_entry_filters` and `analyze_structure_fit`.

Selected field values retain the same causal availability, freshness, coverage and provenance rules. Unrelated sparse datasets are no longer resolved and aged for each observation. Static Dataset matching also reuses immutable Eastern-time formatters instead of constructing them repeatedly per trade; this changes neither DST handling nor timing semantics. Exhaustive `find_predictive_fields` still needs all fields, and paginated `enrich_trades` still returns all fields by design.

### Varchar market fields are categorical

The runtime catalog now uses existing context field-type metadata to recognize varchar market fields such as `Trend_Direction` as **categorical**. Explicit-field `suggest_filters` proposes equality exclusions for their categories, and `analyze_regime_performance` reports category segments instead of incorrectly applying numeric bins. Close-derived values such as `Trend_Direction` still come from the prior session; their timing does not change.

### Missing groups use `group: null`

Missing group values are retained in an explicit row with `group: null`, `groupValue: null` and `uncoveredGroup: true`. A real category named `"uncovered"` remains a distinct string category. Callers should use the null value/flag, not a display-label sentinel, to identify missing groups.

### Admission and new named refusals

Request/candidate and conservative selected-unit work checks run **before field enrichment**, after block loading and strategy/date selection. Permutation budgets now count all selected trades or entry days as an upper bound before coverage is known, rather than resolving every field first. Oversized requests refuse explicitly; no field is silently dropped to fit.

New options have explicit refusal contracts: `day_field_varies`, `day_group_varies`, `objective_requires_day`, `mar_requires_capital`, `mar_undefined`, `group_field_unavailable` and `group_bins_invalid`, detailed below. Existing `permutation_candidate_limit`, `permutation_work_limit` and `permutation_request_work_limit` remain named refusals. Omitted options retain trade-mode outputs; the categorical correction above can change existing varchar-field analyses.

## Large-block latency and entry-day analysis

### Reported fixture timings

The implementation's local measurements used a real-DuckDB fixture with **24,200 trades (2,200 days × 11 entries)**, a daily open-known dataset and **99 seeded month permutations**. Before the change, matching reportedly consumed roughly **5–8 seconds**, followed by **1.5–2.7 seconds** in age summaries, only to refuse work after enrichment. The day path now charges 2,200 daily observations rather than 24,200 independent entries and completes that permutation request.

The recorded post-change end-to-end day-mode calls took about **1.2–1.3 seconds**. A cold first trade-mode work refusal took about **4 seconds**, dominated by block loading before admission. These are reported local fixture measurements, not a new independent benchmark or a universal timeout/latency guarantee. Named computational caps still apply; the work check does not bypass block loading.

### `unit: "day"`

`filter_curve` sums reported P&L by **entry calendar date** before scoring thresholds, yearly/group breakdowns and whole-month permutation. Win rate then counts **days with positive summed P&L**, not winning trades. `winRateBasis` states that convention. Counts describe daily observations in day mode, even where a retained compatibility key says `tradesAnalyzed` or `percentOfTrades`.

Every resolved filter value, including missingness, must agree across all entries on a day. A varying field or a mixture of covered/uncovered entries refuses that field as `day_field_varies`, listing the varying `days`; there is no averaging of field values or arbitrary choice of one entry. Omitting `unit` retains `"trade"` behavior.

For example:

```json
{
  "blockId": "multi-entry",
  "field": "signal.score",
  "unit": "day",
  "objective": "sharpe",
  "groupBy": "Trend_Direction",
  "permutation": { "iterations": 99, "block": "month", "seed": 42 }
}
```

Pass those arguments to `filter_curve`. Group and filter values share causal entry-time resolution and honor `maxMissedSessions`.

## Daily risk objectives

`objective` additionally accepts `sharpe`, `mar` and `maxDrawdown` with `unit: "day"`. Trade units refuse these objectives as `objective_requires_day`. Each threshold reports risk metrics and a baseline-relative objective delta; eligible candidates must keep and remove at least one observation. Ranking uses that objective delta with the existing P&L/win-rate tie-breaks. It still reports the best eligible candidate even if the delta is negative, not only favorable results.

All risk paths use **covered entry dates only**, keeping filtered dates flat at **zero P&L**. Dates without covered entries are not inserted. These are entry-attributed reported-P&L curves, not marked daily account equity.

### Sharpe: daily dollar P&L, rf = 0, √252

Sharpe is mean daily **dollar P&L** divided by its **sample standard deviation**, annualized by **√252**, with **zero risk-free rate**. Zero variance or fewer than two observations returns 0, following the shared simulation helper. No capital is required. This deliberately differs from portfolio return Sharpe's historical Treasury-rate convention; it is not a return-series Sharpe silently using assumed capital.

### MAR: calendar-span CAGR and evidenced starting capital

MAR is calendar-span CAGR divided by drawdown as a fraction of **starting capital**. CAGR uses the first through last covered entry dates and **365.25 calendar days per year**. Calendar-parts day spans prevent local-midnight DST offsets from changing annualization or the stability guard. The drawdown denominator is starting capital, not a rolling-peak percentage.

Capital comes from the existing daily-log/observed-trade-funds resolver, **never its assumed default**. Date-windowed calls restrict daily-log capital evidence to the same `startDate` / `endDate` range as the trades; they do not reuse a pre-window balance.

**A single strategy never borrows portfolio capital.** With `strategy` supplied, portfolio daily logs are excluded entirely: the selected strategy needs its own observed trade-funds evidence. Otherwise MAR refuses with `mar_requires_capital` and `capitalReason: "portfolio_capital_not_applicable_to_strategy"`. Sharpe and dollar drawdown remain available; drawdown percent is null with the corresponding `percentReason`. Without a strategy filter, the existing windowed daily-log/trade-funds policy applies; absent capital is reported as `capital_unavailable`.

Zero drawdown, nonpositive ending capital or no elapsed span makes MAR undefined. Such statistics report null, threshold candidates name `mar_undefined` and cannot rank, and an analysis with no eligible MAR candidate reports a named refusal.

In **per-year and per-group risk rows** whose covered subset spans **fewer than 90 calendar days**, baseline, kept and removed statistics suppress MAR and annualized return: `mar: null`, `annualizedReturnPct: null`, `marUnstable: true`. The row is also marked `marUnstable`, and a MAR objective delta is null. Exactly 90 days remains eligible. This subset guard does not suppress the whole-population objective or alter permutation.

### Maximum drawdown: rank the reduction

`maxDrawdown` reports the positive maximum decline of cumulative daily dollar P&L, starting at zero. It also reports percent of observed starting capital when available. Its objective delta is **baseline drawdown minus kept drawdown**, so a larger reduction ranks better; it does not maximize drawdown. No capital is needed for dollar drawdown, and missing capital is never replaced with an invented percent denominator.

`objectiveMetadata` states these definitions, capital, flat-day treatment and undefined cases. The library now exports `calculateSharpeRatio` and `calculateMaxDrawdown`; drawdown retains its relative default and additionally accepts an `absolute` basis for cumulative dollar P&L beginning at zero.

## Chosen-threshold regime breakdowns

`groupBy` names a registered dataset or built-in market field. It adds `perGroup` beside `perYear`, applying the **same full-sample chosen threshold**, not fitting a different threshold per group. Supplying it opts into `totalPl` selection when no objective is specified.

Rows report the covered baseline, uncovered count/P&L, kept/removed statistics, objective delta and small-sample warnings. Groups partition selected trades/days, including filter-uncovered observations and the explicit null group. Small groups remain visible rather than disappearing. If there is no chosen threshold, there is no fitted breakdown to report.

Numeric groups reuse `analyze_regime_performance` binning: explicit increasing finite `bins` cut points, or quartiles when omitted, with lower-inclusive/upper-exclusive intervals. Categorical groups use their values. Numeric buckets sort by bucket; categories sort lexically; missing groups come last.

Day-mode group values must also agree within each entry day, including missingness. Varying or partially missing group values refuse as `day_group_varies`, naming the dates and group field. Unknown fields refuse as `group_field_unavailable`; bins without `groupBy`, unordered cuts or bins on categorical fields refuse as `group_bins_invalid`.

## Permutation assumptions and work limits remain explicit

Calendar-month permutation reruns the complete objective sweep, including the **permuted baseline risk path** for risk objectives. Day mode permutes summed entry-day P&L. Month blocks retain dependence within a month, not across months; monthly-block exchangeability remains an assumption. Holm adjustment covers only the requested fields in one call, not exploration across calls. `groupBy` adds neither another fitted search nor another Holm family.

The existing caps remain: at most 499 iterations, 100 threshold/percentile entries only when permutation is requested, 30 million estimated work units per field and 90 million per request. Admission counts the selected trade/day unit conservatively before coverage; risk objectives add **36nt path-work units per sweep** to the existing sort/filter estimate (`n` selected observations, `t` requested candidates). A risk request can therefore refuse where a simpler P&L request fits. These limits are not wall-clock promises.
