# Tradeblocks 3.10.0

## Exit thresholds now decide on the figure they report

A percentage exit threshold was multiplied against the entry cost in binary
floating point, so the threshold compared against was not the decimal figure you
configured — and not the figure reported back to you. A 1% stop on a $35 entry
cost evaluated to `0.35000000000000003` while the analysis reported the threshold
as `-$0.35`, so a position whose P&L was exactly `-$0.35` came back as _not having
reached its stop_. The same mismatch affected percentage profit targets and
stepped profit-action thresholds.

The error was small in dollars but could resolve on either side of the decimal
threshold. It also affected `batch_exit_analysis`, where a sweep across stop
levels uses these same comparisons to choose a policy.

Thresholds this analysis derives from your configuration are now resolved to the
nearest millionth of a dollar in exact fixed-point arithmetic, so the threshold
reported and the threshold compared against are one number. This covers
percentage-of-entry-cost targets and stops and profit-action step arms and stops.
Configured dollar thresholds use the same millionth-dollar resolution. Comparisons remain
inclusive. **An exit analysis at one of these boundaries may now gain or lose a
trigger compared with an earlier result.** The new result uses the resolved
figure it reports, but re-run any saved analysis you are relying on.

Replayed position P&L, per-leg-group P&L, trailing drops, and
trigger-versus-actual-exit differences now resolve to the same
nearest-millionth-of-a-dollar grid used by exit thresholds. For analyses that
complete, entry costs used for percentage exits are also resolved per leg before
they are combined, so leg order cannot change the threshold. A position outside
the supported money range fails with an error instead of returning a wrong
result. **An analysis sitting exactly on one of these
boundaries may now gain or lose an exit compared with an earlier result.** Re-run
any saved analysis you rely on. Reported P&L figures keep their existing
two-decimal presentation.

Three further consequences:

- **A derived threshold is reported exactly.** Whole cents print as before, so
  almost every reported figure is unchanged. One carrying real sub-cent precision
  — which a percentage of an entry cost produces routinely — now keeps the digits
  it has, so a stepped floor of `$0.175` reports as `$0.175` rather than `$0.17`
  or `$0.18`, and a 0.5% stop is labelled `0.5%` rather than `1%`. If you parse
  these strings, expect more than two decimal places on sub-cent thresholds.
- **Every monetary threshold has millionth-dollar resolution.** An amount carrying
  finer precision is taken at the nearest millionth, so `$0.0000006` resolves to
  `$0.000001`. Non-finite values and values beyond the largest exactly represented
  amount are refused with a message naming the field. The same rules apply wherever
  the threshold comes from, including one derived from a percentage and an entry
  cost. No field a trigger type ignores is checked, so public request schemas
  remain unchanged.

- **An exit that matched the actual exit is now reported as such.** A trigger and
  an actual exit at the same P&L previously read `Trigger was $0.00 worse.`; it
  now reads `Trigger was the same.` Zero is neither better nor worse.
