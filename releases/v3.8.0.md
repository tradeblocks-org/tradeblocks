# Tradeblocks 3.8.0

## Monte Carlo percentage returns now compound

Percentage-return simulations previously summed the resampled returns and applied
the total to the starting capital. Despite the method being documented as
compounding, capital never compounded from one trade to the next. On a real
83-trade history that grew from $1,000,000 to $2,497,421, resampling that
history's own returns over its own length produced a median final value of
$1.94M — 22% below the equity the return stream actually produced.

Returns now compound trade by trade. A single trade cannot lose more than the
account (returns clamp at -100%), and an account that reaches zero stays there.
Together with the existing -99% floor on margin-based returns, that replaces the
former additive arithmetic as the guard against pathological sequential losses.

**Medians, drawdowns, and both return tails all move upward.** Re-baseline saved
comparisons, alert thresholds, and any stored simulation output when upgrading.

## Stationary block resampling is the new default

Simulations now resample runs of consecutive trades rather than drawing trades
independently, preserving the clustering that real trade histories exhibit.
Block lengths are geometrically distributed with a mean that defaults to the cube
root of the resample pool size.

Pass `resampleMode: "iid"` for the previous independent-draw behavior, or
`meanBlockLength` to set the mean block length explicitly. Block resampling
mainly widens simulated drawdowns and tails; the typical outcome barely moves.

## Risk of ruin and zero-balance paths

Every simulation now reports `zeroBalancePaths`, the share of paths whose equity
ever reaches zero. Supply `ruinThresholdPct` — a decline from starting capital,
as a decimal — to also receive `probabilityOfRuin`, the share of paths that ever
fall to or below that floor. A threshold of 0 is rejected rather than silently
placing the ruin floor at starting capital, which would have reported nearly
every path as ruined.

## `run_monte_carlo` parameters and results

The tool accepts `resampleMode`, `meanBlockLength`, and `ruinThresholdPct`, and
returns `zeroBalancePaths`, `probabilityOfRuin`, and the effective parameters the
run actually used — including the resolved mean block length, which now accounts
for synthetic worst-case trades injected into the pool. `portfolio_health_check`
additionally reports the zero-balance share.

## Risk Simulator

The simulated horizon now defaults to the loaded history instead of a fixed
period derived from trading frequency. An 83-trade history previously defaulted
to a 40-trade simulation, so results silently disagreed with any tool that
projects a history's own length. The horizon follows the active strategy filter,
never overwrites a value you set by hand, and says when a manual horizon no
longer matches the history it was typed for.

The projection chart overlays your actual equity path in its original order, so
simulated dispersion is always anchored to what really happened, and a Reality
Check panel reports that actual final value alongside the zero-balance and ruin
figures. Exports carry the new parameters and statistics.

## Identifiers no longer require a secure context

Creating a block or a saved configuration used `crypto.randomUUID`, which is
undefined outside a secure context. Serving the application over plain HTTP on a
LAN address therefore failed on upload. Identifier generation now falls back to
`crypto.getRandomValues` and remains a valid UUID.

## Dependency hygiene

Three high-severity advisories are closed by pinning patched versions of
`@babel/core`, `postcss`, and `minimatch` — the last of which also supplies the
patched `brace-expansion`. `npm audit --audit-level=high` reports no high or
critical findings.
