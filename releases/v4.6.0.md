# TradeBlocks 4.6.0

**New tool `import_option_archive` bulk-imports option quotes from a local Parquet archive without calling a provider. `filter_curve`'s permutation work limits can be raised on a self-hosted server, and a permutation that could never reject now says so.**

4.6.0 ships tradeblocks#595 and further tradeblocks#586 work, both contributed by @carstenf. CSV import and existing tools are unchanged.

## New tool

### `import_option_archive`: bulk import of option quotes from a local Parquet archive

The tool imports 1-minute NBBO option quotes from a directory or glob of Parquet day files (for example a ThetaData dump) into the `option_quote_minutes` and `option_chain` partitions. You can filter by date range, DTE, rights and strike band. Each day gets a row-count check, and `dryRun` returns the plan and an estimate without writing.

- **Existing days.** Days that already hold option data are skipped by default (`onExisting: "skip"`), so a narrower import never deletes a broader one. `onExisting: "replace"` rewrites them. If the tool cannot determine whether a day holds data, it reports the day in `days.errors` and does not write it.
- **Failed writes.** A failed write restores the day. A refused quote write publishes nothing, and a failed chain write restores the previous quote partition (or removes it for a new day). If an interrupted run leaves a day half-written, `onExisting: "replace"` repairs it.
- **Result fields.** The result lists:
  - imported out-of-calendar days (`days.unclassifiedDays`): XNYS closures are known for 2022–2030, and outside that range only weekends are excluded;
  - rows dated off the file's day (`days.offDateRows`);
  - the strike reference used for each day (`strikeReference`).
- **Validation.** `underlying` and `tickerRoot` are validated.
- **Time zones.** A naive `timestamp` column is read as America/New_York wall-clock time, so results do not depend on the host time zone.

See `docs/mcp-tools.md` § `import_option_archive` for the archive contract and parameters.

## Behavior changes

### `filter_curve`: configurable permutation work limits and a power warning

On a self-hosted server, two environment variables can now raise the permutation work limits of `filter_curve` (tradeblocks#586):

- `TRADEBLOCKS_PERMUTATION_WORK_LIMIT`, per field (default 30,000,000 work units);
- `TRADEBLOCKS_PERMUTATION_REQUEST_WORK_LIMIT`, per request (default 90,000,000).

Left unset, behavior is unchanged. A value that is not a positive integer refuses the permutation with `permutation_work_limit_config_invalid` instead of falling back to the default.

Work-limit refusals now report the effective limits (`workLimits`) and `minimumIterationsToReject` next to `maxIterationsThatFit`.

Sometimes the admitted iterations cannot reach m/(B+1) < 0.05 for m tested fields. The response then carries a `permutation_cannot_reject` warning with the minimum number of iterations needed, so a result that could never reject is not read as evidence against the filter.

## Compatibility

- No existing tool input changes, and existing outputs change only additively: `filter_curve` refusals gain `workLimits` and `minimumIterationsToReject`, and a response can carry the new `permutation_cannot_reject` warning. `import_option_archive` is a new tool, and the two `filter_curve` environment variables are optional.
- No credential is needed for any of these changes. CSV import still works without a market-data provider.
